Finding your data

Building a query

A query is just a filter — “give me the rows that match.” You build the same filter three ways: by clicking in DataGrouper, or with one line in MATLAB or Python. Below: the operators you combine for any query (each with a real, verified example), then computed columns, summaries, and saving a query for reuse.

The one idea that makes it click

On the command line you start from a table and combine it with a few operators — and most operators take another table as their argument (“datasets that have a drug tag,” “datasets without a suspect flag”), which is exactly what DataGrouper’s view levels and Restrict by selection do under the hood. Because the tables share keys (see Data levels), DataJoint works out the join.

OperationMATLABPython
Restrict (keep matches)rel & condrel & cond
Exclude (drop matches)rel - otherrel - other
Join (combine columns)a * ba * b
Project (pick/compute cols)proj(rel, …)rel.proj(…)
Aggregate (summarize groups)aggr(a, b, 'e->n')a.aggr(b, n='e')
Union (stack rows)a | ba + b
Count / fetchrel.count · fetch(rel,'*')len(rel) · rel.fetch()
The one real difference Union is | in MATLAB but + in Python. Everything else is spelled the same. (Schema loading in Python is up to you — the snippets assume sln_symphony etc. are already imported; there’s no aka.* in Python.)

The building blocks

Five operators cover almost every filter. Each example is real; the counts are from the live database.

Restriction  &✓ verified

Keep rows that match a condition

MATLAB
datasets = sln_symphony.Dataset & 'file_name LIKE "101323A%"';
datasets.count        % -> 32
Python
datasets = sln_symphony.Dataset & 'file_name LIKE "101323A%"'
len(datasets)         # -> 32

You can also restrict by another table — datasets carrying a drug tag: Dataset & (UserParamDatasetDrugPresent & 'drug_present IS NOT NULL') → 275.

Exclusion  -✓ verified

Drop rows that appear in another table

MATLAB
good = sln_symphony.Dataset - sln_symphony.UserParamDatasetQualitySuspect;
good.count            % -> 15650  (datasets not flagged suspect)
Python
good = sln_symphony.Dataset - sln_symphony.UserParamDatasetQualitySuspect
len(good)             # -> 15650

Join  *✓ verified

Pair rows and combine their columns

MATLAB
dd = sln_symphony.Dataset * sln_symphony.UserParamDatasetDrugPresent;
dd.count              % -> 16447
Python
dd = sln_symphony.Dataset * sln_symphony.UserParamDatasetDrugPresent
len(dd)               # -> 16447

Joins line two tables up on their shared keys. (More rows than datasets here because a dataset can have several drug entries.) — but watch out when a column name is shared by accident; see Advanced below.

Projection  proj✓ verified

Choose just the columns you want

MATLAB
pos = proj(sln_symphony.ExperimentCell, 'cell_number', 'x', 'y');
pos.count             % -> 7950  (one row per cell)
Python
pos = sln_symphony.ExperimentCell.proj('cell_number', 'x', 'y')
len(pos)              # -> 7950

Union  | / +✓ verified

Stack rows from same-shaped relations

MATLAB
s = (sln_symphony.Dataset & 'file_name LIKE "101323A%"') | ...
    (sln_symphony.Dataset & 'file_name LIKE "101323B%"');
Python
s = ((sln_symphony.Dataset & 'file_name LIKE "101323A%"')
     + (sln_symphony.Dataset & 'file_name LIKE "101323B%"'))

Remember: MATLAB |, Python +. Nothing runs until you ask — add .count / len(), or fetch (Exporting data).

Advanced: computed columns & summaries

Two operators do the heavy lifting the GUI can’t: proj computes/renames columns, and aggr summarizes groups. These examples are drawn straight from functions the lab already runs.

Projection that computes · sln_cell.CellName

Build a readable name from parts

MATLAB
% exactly what sln_cell.CellName does:
cells = proj(sln_symphony.ExperimentCell, ...
             'concat(file_name, "c", cell_number) -> cell_name');
fetch(cells, 'cell_name')     % e.g. "101323Ac3"
Python
cells = sln_symphony.ExperimentCell.proj(
            cell_name='concat(file_name, "c", cell_number)')
cells.fetch('cell_name')      # e.g. "101323Ac3"

proj can make a new column from a SQL expression. MATLAB puts it all in a string with ->; Python uses new_name='expression'. (proj never changes the row count.)

Join that needs a rename · sln_cell.RetinaQuadrant

When two tables share a column name by accident

A retina’s key is source_id; a cell refers to its retina through a column called retina_id. A plain ExperimentCell * ExperimentRetina would try to match the cell’s own source_id against the retina’s — wrong things, same name. Rename first, then join (this is the move inside sln_cell.RetinaQuadrant):

MATLAB
% rename source_id -> retina_id, keep all other columns ('*'), then join:
retinas = proj(sln_symphony.ExperimentRetina, 'source_id -> retina_id', '*');
cells   = sln_symphony.ExperimentCell * retinas;
Python
retinas = sln_symphony.ExperimentRetina.proj(..., retina_id='source_id')
cells   = sln_symphony.ExperimentCell * retinas

The same thing bites when you join a result table to the dataset and both carry user_name (who recorded the data vs. who computed the result) — the join collapses to almost nothing. Rename one side first, e.g. proj(sln_results.DatasetSMSCA, 'user_name -> analysis_user', '*'), then *. In MATLAB '*' keeps all columns; in Python the ... does.

Aggregation · aggr

Summarize a group into one number

MATLAB
% how many epochs are in each dataset?
counts = aggr(sln_symphony.Dataset, sln_symphony.DatasetEpoch, ...
              'count(*) -> n_epochs');
Python
counts = sln_symphony.Dataset.aggr(
             sln_symphony.DatasetEpoch, n_epochs='count(*)')

Reads as: group Dataset, count its DatasetEpoch rows into n_epochs. Grouping table first, counted table second, computed attribute as 'expr -> name' (MATLAB) / name='expr' (Python). Other aggregations: avg(x), max(x), group_concat(…). For a real production example nesting aggr and proj, read sln_animal.GenotypeString.

Build once, reuse

Some filters (e.g. “all ON-alpha cells”) are too tangled to type — a cell’s type is its latest assignment event, so the real query spans ~10 joins. For those, build the query once and save it. Two ways, same result — a row in sln_lab.Query:

In DataGrouper

Build it visually, then Save query under a name and project.

From the command line

You don’t have to use the GUI — save any relation you built with sln_lab.saveQuery (your user name is filled in automatically):

MATLAB
rel = sln_symphony.Dataset & 'file_name LIKE "101323A%"';
sln_lab.saveQuery(rel, 'rigA_101323');                       % minimal
sln_lab.saveQuery(rel, 'rigA_101323', 'my_project', true);   % project + overwrite

Reuse it anywhere

Re-run by name from QueryBrowser, or from code:

MATLAB
q = sln_lab.Query & 'query_name = "Ref_SMS_CA_ON_alpha"';
datasets = q.runAndFetch();
There's already a library The lab has 70+ saved queries in sln_lab.Query — browse them in QueryBrowser before building a new one. (saveQuery is a MATLAB helper; from Python you insert into sln_lab.Query directly with your relation’s SQL. And query_name can repeat across users — add & 'user_name = "…"' if a fetch is ambiguous.)
Once you have a query Count it, plot it, run an analysis on it, or export it — the same whether you built it by clicking or typing.
